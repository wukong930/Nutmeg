## §1 为什么推翻 v1.9:前提是假的

v1.9 引入随机效应收缩的**唯一**理由是「δ₊₁ 自己站不住」(t=1.83,判闸下界
−0.0023,不做功)。而那个「测不出」来自一个**漏了别名层的 join**:

`scripts/handicap_delta_homogeneity.py` 两侧都只做 `normalize_name`,跳过了
`to_v4_canonical` 的解析链(精确→归一化→**别名**→模糊)⇒「Manchester United」
永远对不上「Man United」,**59% 的样本被静默丢弃**。这正是项目自己记着的规则
「跨源 join 别裸 normalize_name」,被我写的脚本破掉。

改走解析器(**模糊关闭**,只走精确/归一化/别名,`TEAM_ALIASES` 一条新别名没加):

```
join 命中  3,038/7,381 (41%) → 4,938/7,381 (67%)   解析方式 exact 3,761 · alias 1,177
可用样本   3,038 → 4,934 (+62%)     −1: 1,958→3,131 · +1: 1,080→1,803
```

| | 修前 | 修后 |
|---|---|---|
| δ₋₁ | 0.0456 ± 0.0098 (t=4.65) | **0.0463 ± 0.0078 (t=5.92)** |
| δ₊₁ | 0.0241 ± 0.0132 (**t=1.83**) | **0.0320 ± 0.0101 (t=3.16)** |
| δ₊₁ 判闸下界 | **−0.0023**(负,不做功) | **+0.0118**(正)✅ |

⇒ **两条线各自独立确立,不需要借力** ⇒ 收缩(v1.9)与完全合并(曾考虑的③)
**同时作废**。k=2 上估 τ 的批评也随之 moot。

⚠️ **别误读的巧合**:v1.9 收缩出的 0.03220 与 v2.0 独立估的 0.0320 几乎相同。
那是「借力方向恰好对」的运气,不是方法对。它说明的只是:v1.9 部署期间 +1 的
判闸没有把线上带偏。

## §2 δ 与 SE 必须同时换(不许只换点估)

线上原 SE(0.00693 / 0.00787)是**收缩模型**的产物 —— 它们之所以小,正是因为
两条线在互相借精度。既然放弃借力,SE 必须回到各自诚实的聚类 SE。
**用新 δ 配旧 SE = 把两个模型的零件拼在一起**,判闸会得到一个谁也没测过的量。
