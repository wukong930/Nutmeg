# 球员级 xG/xA 特征 — 数据门控结论存档

> 运行:2026-06-01 · 对应"模型评估"文章 #6"加市场没吸收的信息 → 球员级 xG/xA/防守贡献"

## 问题

队级 xG 不够,关键球员变化更重要——该不该加球员级 xG/xA 特征?

## 与 β / 战意的根本区别:这条没法廉价验证

| 测什么 | 能不能"先测后建" |
|---|---|
| β(独立信号) | 能——混合两个现成概率向量 |
| 战意 | 能——从结果重建积分榜 |
| **球员级 xG/xA** | **不能——信号 = 特征本身,必须先抓数据、建管线、重训、ablation** |

## 数据查证(2026-06-01)

| 查的东西 | 结果 |
|---|---|
| `data/external/` 有无球员级 / Understat 数据 | **无**(仅 clubelo / api_football / cup / elo / odds / logos) |
| 任何 player / xg 数据文件 | **零** |
| Understat 抓取器(`data/sources/understat.py`,V5 W3 写) | 代码在,**从未真抓**(落盘为空) |
| `xg_lite` | **队级**——从 football-data `home_shots`/`away_shots`/`SoT` 推,无球员分辨率 |

→ 要验证须先去 Understat/FBref 抓事件级球员 xG/xA。

## 三个现有数据点已框住"回测天花板"

1. **阵容感知模型(V6 W6/W7,已建)**:lineup 是"谁上场"的粗版(球员 xG 是细版)。回测改善约 **−0.002 ~ −0.004** log-loss,**4 周 ROI 从未验证**(数据门控)。
2. **market_dynamics(开盘→收盘路径)ablation 失败**:收盘线已吸收开盘+盘路的一切,含阵容引起的赔率移动 → **任何特征打不过收盘线**。
3. **β 测试**:模型在 1X2 收盘相对 Pinnacle **零独立信号**。

合起来 → **球员 xG 特征回测上限很低**:最多帮模型**贴近** Pinnacle(Pinnacle 开赛时早已 price 进阵容),**产生不了对 Pinnacle 的 edge**。

## 唯一真正的 edge:soft book 反应慢(文章自己点了)

> "首发公布后但 soft book 尚未充分反应"

真 edge 不在收盘线,而在**首发公布(开赛前 ~1h)→ 竞彩更新 SP 之间的窗口**:竞彩对"关键球员缺阵"反应慢 + 我们用球员 xG 量化影响 = 真钱。

**但这是实时操作流,不是历史特征**:需要实时阵容流 + 球员 xG 影响计算 + 窗口内轮询竞彩 SP。是 #6 里**最可能有真 edge** 的一条,也是**最重**的一条——我们没有这套基础设施。

## 决策:数据门控,现在不建

- **回测上限低**(Pinnacle 收盘已 price 阵容;market_dynamics 已证收盘线打不过)。
- **真 edge 要一套我们没有的实时管线**(soft-book 滞后窗口)。
- **零实盘 ROI** 支撑不了这笔几周 + 持续数据成本的投资。

**与战意的区别**:战意是"**测了、信号 ≤1.5σ**";球员 xG 是"**有合理的真 edge 故事(soft-book 滞后),但要先砸数据 + 实时管线才能拿到**"。

→ **它是 #6 里 IF 将来搭了"实时竞彩 SP 监控",最值得回头做的一条。** 在那之前,搁置。

## 如果坚持要个数(最便宜的真验证路径)

抓 1 个联赛 × 1-2 赛季 Understat 球员 xG,做小 ablation,看球员级比队级 xg_lite 多挤出多少。**但:就算挤出 −0.003,也只是贴近 Pinnacle、不产生 edge**——真 edge 仍要靠那个实时窗口。
