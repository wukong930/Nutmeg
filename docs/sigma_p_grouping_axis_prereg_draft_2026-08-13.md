## §2 理由(**先验的**,不是「因为数字更好看」)

### ①「轨迹」的物理对象是**市场**,不是**观测者**

σ_P(h) 要测的是:**Pinnacle 的线随距开球时间怎么抖**。那是盘口的属性。
`source` 是**我们自己的代码路径**(哪个 CLI/端点发起了这次抓取),
和线怎么动**没有任何关系**。按它切轨迹 = 把同一条市场轨迹拆成几段互相看不见的碎片。

### ② 前提已被实测证实:各 source 看到的是同一条线

**1544 / 1544 组**中,同一场同一时刻不同 source 记录的价格**完全相同**。
⇒ 「不同 source 是不同测量仪器、各有各的噪声」这个可能的反驳,**不成立**。

### ③ 现状会系统性**低估**国内层 σ_P

按 source 切 ⇒ 每条碎片的「最靠近开球的点」都比池化后更远:

```
锚的中位 h    0.307 → 0.156(减半)
每轨点数      9 → 32
```

而闸是「锚 ≤1.5h 否则整条丢弃」⇒ 现状既**丢掉更多轨迹**,留下的又**锚得更远**。
杯赛层锚几乎没动(0.490→0.458)而杯赛效应正好 null —— 两层方向与量级自洽。

### ④ 它顺带解决了「跨 source 去重」那个口径不一致

去重不带 source(按比赛),而分析按 (比赛, source) —— 本来就是两个轴。
**把分析轴对齐到去重轴**,不一致自然消失,且**不需要动共享表**
(动表:17 个读取点、+23~51% 行数、队名歧义闸反噬,详见测量报告 §6)。

## §3 采纳 (A) 的前提检验(**这几条不过就不改**)

⭐ 这些是**先验**能写下来的,与「改完数字变多少」无关:

**① 池化不许把不同市场混在一起 —— ✅ 已查根因,规则改了**

   ⚠️ **初稿的事实基础错了两处**(测量报告 §5② 已更正):
   - 「390/1133 场(34%)」→ 其中 **349 场(89.5%)差 0 分钟**,只是
     `+00:00` vs `Z` 的字符串格式差。真时刻不同 **41 场 / 1133 = 3.6%**
   - 「常见差 1 小时」→ 差 60 分钟只有 **3 场**;众数是 **MLS +10 分钟(29 场)**

   **根因(2026-08-13):不是 bug,是两个上游的两种合法语义。**

   | 源 | 字段 | 语义 | 更新? |
   |---|---|---|---|
   | `closing` | Odds API `commence_time` | **实际**开球 | ✅ 延后时上游改 |
   | 其余四源 | API-Football `fixture.date` | **排定**开球 | ❌ 从不改 |

   实测:41/41 **单调后移**;27 场改在原定开球前 1h 内、6 场改在开球**之后**;
   改的只有 `closing`(29)和 `cup_market`(8),`predict_log`/`sp_calc`/`ingest_odds` **0**。
   ✅ 顺手排除了「延后会让赛中盘绕过 `kickoff<=now` 守卫」:17 行确在原定开球后抓,
   但 booksum 1.033–1.059(赛前中位 1.034)、主胜相对移动中位 **1.68%**
   (赛中 1-0 会动 30–60%)⇒ 全是赛前线,守卫用的是与赔率同源的那个 kickoff、自洽。

   **影响 ≈ 0**:逐行 h 与该场众数开球的偏差**中位 0.000h**;跨 1.5h 闸翻转 **1/1464 行**。

   ⇒ **规则(已实现):取该场 `kickoff_utc` 的 `max`**,不是众数。
   理由:41/41 单调后移,最晚的那个来自会更新成实际开球的上游 ——
   **众数会系统性选中「陈旧的排定时刻」**,恰好选错。
   护栏:同场 kickoff 跨度 > `_KO_SPREAD_MAX_H = 3.0` ⇒ **整条丢弃并计数**
   (实测最大跨度 1.0h ⇒ 这是纯护栏、不是筛子,今天丢 0 条)。
   丢弃数**必须出现在仪表里**(不许静默)。

**② 自举单元 —— ⚠️ 本条初稿写错了,方向是反的**

   初稿写「`_boot()` 按点重采样 ⇒ 池化后 CI 会假性收窄,采纳前必须先改」。
   **查源码后作废**:根本没有 `_boot()`;真正的函数是 `bootstrap_coefs`
   (`sigma_p_fit.py:155`),它**按轨迹**重采样,docstring 明写
   「按**轨迹**自举(不是按增量)—— 同一场的多个桶相关,按增量自举会高估精度」:

   ```python
   samp = [trajs[rng.randrange(n)] for _ in range(n)]
   ```

   ⇒ 真实情况**与初稿相反**:
   - **现状**:单元 = (比赛, source)。同一场最多 5 条**高度相关**的轨迹被当作
     5 个独立单元 ⇒ **今天的 CI 就已经偏窄**
   - **池化后**:单元 = 比赛,一场一个 ⇒ 相关性问题**变小**,CI 更诚实

   **⇒ 这条不是前提,是换轴的又一个理由。**

   📌 残留(池化前后**都存在**,本提议不改善也不恶化):两者都**没有**按比赛日聚类,
   同日多场仍被当作独立。这是既有局限,若要修是另一件事,别混进本议题。

   🚨 **上面这段「别混进本议题」当天就被推翻了 —— 见 §3⑤。**
   写它时我只知道全池有 55 个比赛日,那种密度下按比赛自举确实够用;
   量到**评估人口只有 4 个簇**之后,它就从「既有局限」变成了「读数是虚的」。
   ⭐ **同一个事实,在知道人口规模之前和之后,严重性差一个量级** ——
   「这是既有问题所以不归我管」是个太顺手的挡箭牌。

**③ `N` 的单位变了,阈值必须换算(⭐ 已实测,方向与直觉相反)**

   v2.1 §3 的 `NEXT_EVAL_N = 300` 数的是**轨迹**。池化后单位变成**比赛**。
   **实测(2026-08-13):**

   | 切片 | 现状(比赛,source) | 池化(比赛) |
   |---|---:|---:|
   | 13 训练联赛(评估点人口) | **93 条** | **75 场** |
   | 全池 | 749 条 | 533 场 |
   | 换算比 | — | **≈1.41 条/场** |

   ⭐ **池化让 N 变小、评估点变更远,不是更近。**
   这是个**好性质**:换轴**不可能**成为「提前够到评估点」的后门,
   §0 里担心的那个方向不存在。

   ⚠️ 但也因此,`N_match = 300` 会比旧阈值**严 1.41 倍**,没有理由那么严。
   更根本的是:**两个单位都只是代理** —— CI 由**独立簇数(比赛日)**驱动,
   而比赛日在池化前后**完全不变**(55 个)。池化不增加独立信息,
   它只是把同一条线的重复视角合并掉。

   🚨 **写这条时量出了比换轴更严重的事:13 训练联赛的独立簇数 = 4。**

   ```
   13 训练联赛的 75 场合格比赛,全部坐落在  2026-08-07(9) / 08-08(38) /
   08-09(27) / 08-10(1)  —— 一个赛程轮,且只覆盖 6/13 个联赛
   (德乙11 荷甲15 葡超14 法乙9 比甲12 日职14)
   ```

   ⇒ 现行 `NEXT_EVAL_N = 300`(数轨迹)会在**约 4 个赛程轮 ≈ 4 周**后触发,
   那时独立簇只有 ~16 个。**用 93 个高度相关的单元冒充 93 个独立观测**,
   报出的 CI 是虚的。这不是「单位换算」问题,是**现行阈值在数一个几乎无信息的量**。

   ⇒ **定值(在跑新拟合之前写死,2026-08-13):**

   ```python
   NEXT_EVAL_N        = 300    # 保持原值不动(见下)
   NEXT_EVAL_CLUSTERS = 30     # 新增:13 训练联赛的**比赛日**数
   ```

   **两条同时满足才算到评估点(AND,不是 OR)。**

   依据,三条,全部先验:
   1. **30 是聚类稳健推断的常规下界** —— 簇数 <30 时 cluster-robust 方差估计
      向下偏、t 检验过度拒绝。这是**惯例不是本项目的功效计算**,如实标注。
   2. **`NEXT_EVAL_N` 刻意不换算。** 池化让 13 联赛的单元 93 → 75(**变少**),
      按 1.41 条/场换算「应该」把它降到 ~213。⛔ 不降。
      保持 300 = 让**换轴在数学上不可能把评估点提前**,把 §0 的 look-then-write
      风险钉死在保守一侧。代价是比理论上必要的严 1.41 倍 —— 认了。
   3. **30 簇比 300 轨迹更远。** 欧洲联赛约 3–4 个比赛日/周 ⇒ 300 轨迹 ≈ 4 周
      (~16 簇),30 簇 ≈ 8–10 周。**新闸严格晚于旧闸触发**,不是后门。

   同时保留「≥5 个桶 N ≥ 20」不变(桶级约束,不吃单位)。

**⑤ 自举必须按比赛日聚类(⭐ 由 ③ 的发现倒逼,同批实现)**

   `bootstrap_coefs` / `homogeneity_z` 原本按**轨迹**重采样。池化后轨迹 = 比赛,
   但 75 场只坐落在 4 个比赛日上 ⇒ 按比赛重采样仍然把强相关单元当独立,
   **CI 依旧是虚的**(初稿 §3② 把这条写成「既有局限,别混进本议题」——
   在只知道「55 个比赛日」时那判断是合理的,知道评估人口只有 **4** 个之后不再成立)。

   ⇒ 改为**簇自举**:重采样比赛日,整天的轨迹一起进出。

   ⚠️ **方向是保守的**:它只会让所有 CI **变宽**,包括本草案 §2③ 报的
   「+23.7% [+14.4, +34.1]」。也就是说这条修正**削弱我自己的论据** ——
   这正是它不构成 look-then-write 后门的证明。

**④ 冻结记录不受影响**
   `scripts/sigma_p_refit_floor.py` 是 **v2.0 预注册的冻结执行记录**
   (docstring 明写「必须冻结,别重构」)。它按旧轴跑的数字**保持有效且不重跑** ——
   它记录的是「当时按当时口径得到了什么」,那是历史事实。
   ⇒ 采纳后必须在该文件加一行注记:**它与新轴的产出不可直接比较**。
